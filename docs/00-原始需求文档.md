# TV 版 Bilibili 播放器开发文档

**项目名称**：BiliTV-Web（暂定）
**目标平台**：Android TV（兼容 Fire TV、安卓平板横屏）
**技术路线**：Web 前端（重写 B 站页面）+ WebView 容器 + APK 打包
**UI 参考**：BBLL（第三方 B 站 TV 客户端）完全借鉴
**文档版本**：v2.0


## 一、项目概述

本项目旨在开发一款运行于 Android TV 端的 Bilibili 第三方播放器。核心策略是**基于 B 站 Web 公开接口，通过重写适配电视端的 Web 页面，以 WebView 容器承载并打包为 APK**，在规避 B 站 API 风控的同时，提供适配遥控器操作的大屏观影体验。

**UI 层面**，界面布局、功能分区、控件尺寸、交互逻辑**完全借鉴 BBLL**。BBLL 的全套页面布局深度适配大屏横屏比例，图标大小适中、排版疏密合理、遥控焦点精准移动，大屏浏览无违和、无界面拉伸、文字无溢出，远距离观看清晰护眼。其左侧导航栏布局清晰，适配遥控器操作，默认暗黑模式，左右两侧布局。

**技术层面**，内部逻辑通过 B 站 Web 公开 API 实现，利用 WebView 的真实浏览器环境（完整的 JS 执行、localStorage 密钥缓存、真实渲染上下文）来降低风控特征。B 站风控体系会检测 WebView 渲染上下文、localStorage 密钥缓存、performance.now() 时间戳偏移等行为特征，WebView 方案的浏览器环境真实性优势明显。

### 选择 Web 路线的原因

- **规避 API 风控**：`bilibili-API-collect` 项目已收到 B 站官方律师函，导致多个第三方项目停止 API 功能更新。直接调用 API 的方案面临越来越大的法律和技术风险，而 WebView 中的请求天然携带完整的浏览器环境特征，风控特征远少于裸 HTTP 请求。
- **页面自主可控**：所有 UI 元素由自己编写，可彻底重写为适合 10 英尺观看距离和遥控器操作的布局。
- **开发效率高**：一套 Web 技术栈，无需学习 Android 原生开发。

## 三、技术选型

### 3.1 前端技术栈

| 层面 | 选型 | 理由 |
|------|------|------|
| 前端框架 | Vite + Vue 3 / React | Vite 构建快，产物为纯静态文件 |
| 路由 | Hash 路由 | 避免 WebView 直接访问子路径 404 |
| 遥控器焦点 | tvcontroller-javascript | 属性式声明，零学习成本，明确支持 Android TV 和 Fire TV |
| HTTP 客户端 | 浏览器原生 fetch / axios | 在 WebView 中使用，携带完整浏览器环境 |

tvcontroller-javascript 通过简单的 HTML 属性即可实现遥控器导航：`tv-focus="true"` 标记可聚焦元素，`tv-enter` 定义确认键行为，`tv-back` 定义返回键行为，支持 Samsung Tizen、LG webOS、Android TV、Fire TV 等平台。

**备选焦点方案**：`@chancestv/tv-focus` 支持按屏幕几何位置移动焦点、分区管理和模态层栈，面向低版本 WebView（Chromium 53+）设计。如果对空间导航有更高要求（如复杂网格布局），可考虑此方案。

### 3.2 打包工具选型

#### 方案一：Nitron（推荐优先尝试）

Nitron 是一款极简的 HTML/CSS/JS → APK 构建工具，核心理念是“让 Android 完全隐形”。

**核心优势**：
- **零 Android SDK 依赖**：无需安装 Android Studio、Gradle、JDK，运行一条命令即可出 APK。
- **微架构**：整个 Android 运行时仅 **9.6 KB**（classes.dex），不引入臃肿的 WebView 框架。
- **HTTPS 本地源**：使用 `appassets.androidplatform.net` 替代 `file://` 协议，彻底解决 CORS、Cookie、localStorage 问题。绝对路径、fetch() 请求、Cookies 和 localStorage 均可正常工作。
- **构建速度快**：3 秒内生成可安装的 APK。
- **Framework Presets**：支持 `--preset` 参数，可快速为 Vite、React、Next.js 项目生成配置。

**快速上手**：
```bash
# 1. 前端项目初始化（以 Vite + Vue 为例）
npm create vite@latest bilitv-web -- --template vue
cd bilitv-web

# 2. 安装依赖
npm install tvcontroller-javascript

# 3. 构建前端
npm run build

# 4. 初始化 Nitron
npx nitron init --preset vanilla

# 5. 生成 APK
npx nitron build
# 输出：dist/app.apk
```

配置文件 `nitron.config.json` 示例：
```json
{
  "name": "BiliTV",
  "packageId": "com.yourname.bilitv",
  "version": "1.0.0",
  "entry": "dist/index.html",
  "orientation": "landscape",
  "permissions": ["INTERNET", "ACCESS_NETWORK_STATE"],
  "network": { "cleartext": false },
  "webview": {
    "backButton": "history",
    "clearCacheOnStart": false
  },
  "splashScreen": { "backgroundColor": "#1a1a2e" }
}
```

**注意事项**：Nitron 在 npm 上周下载量约 **389** 次，属于较小众的工具，遇到问题时社区资源有限。建议在初期快速验证阶段使用，如果后续需要更深入的原生层调整，再迁移到 Capacitor。

#### 方案二：Capacitor（稳健备选）

Capacitor 由 Ionic 团队维护，是 Web → Android 打包领域最成熟的方案，生态完善，文档齐全，生成的 Android 工程是标准 Gradle 项目，随时可打开 Android Studio 微调。

Capacitor 已确认支持 Android TV 的 Leanback Launcher 和 D-pad 遥控器导航。需要在 `AndroidManifest.xml` 中声明 Leanback 支持：

```xml
<uses-feature android:name="android.software.leanback" android:required="false" />
<uses-feature android:name="android.hardware.touchscreen" android:required="false" />
```

在 `build.gradle` 中添加 Leanback 依赖：
```groovy
dependencies {
    def leanback_version = "1.2.0"
    implementation "androidx.leanback:leanback:$leanback_version"
}
```

**Capacitor vs Nitron 对比**：

| 维度 | Nitron | Capacitor |
|------|--------|-----------|
| 上手门槛 | 极低，无需 Android SDK | 中等，需 Android Studio |
| 社区生态 | 小众（周下载 389） | 成熟，文档完善 |
| 原生层控制 | 有限 | 完全开放 |
| 构建速度 | 秒级 | 分钟级 |
| 适合阶段 | 快速原型验证 | 长期维护迭代 |

## 五、遥控器焦点管理

### 5.1 核心原理

Android TV 遥控器的方向键、确认键、返回键在 WebView 中会以标准键盘事件（`keydown`/`keyup`）形式触发，键码为：方向键 37-40，确认键 13，返回键 4。因此，只需在 Web 页面中监听键盘事件并管理焦点，即可实现遥控器操作。

**关键注意事项**：D-pad 事件可能被原生应用层消费，需要在原生层将相关按键传递到 WebView 的 JS 层。如果使用全屏 WebView，可以确保按键事件正确传递。开发者应处理好网页应用中的焦点，将初始焦点设置到启动时可操作的元素，以便用户从第一次按键时就能开始使用应用。

### 5.2 使用 tvcontroller-javascript

**安装与初始化**：
```bash
npm install tvcontroller-javascript
```

```javascript
import { tvController } from "tvcontroller-javascript";
tvController().init();
```

**标记可交互元素**：

```html
<!-- 导航菜单 -->
<div tv-focus="true" tv-enter="navigateToHome()">首页</div>
<div tv-focus="true" tv-enter="navigateToSearch()">搜索</div>

<!-- 视频卡片 -->
<div class="video-card" tv-focus="true" tv-enter="playVideo('BV1xx411c7mD')">
  <img src="cover.jpg" alt="视频封面">
  <span>视频标题</span>
</div>

<!-- 播放器控制 -->
<button tv-focus="true" tv-enter="togglePlay()">⏯ 播放/暂停</button>
<button tv-focus="true" tv-enter="rewind()">⏪ -10s</button>
<button tv-focus="true" tv-enter="forward()">⏩ +10s</button>
```

**属性说明**：

| 属性 | 说明 |
|------|------|
| `tv-focus="true"` | 标记元素可被遥控器聚焦 |
| `tv-enter="..."` | 按下确认键时执行 |
| `tv-focused="..."` | 聚焦时触发 |
| `tv-back="..."` | 按下返回键时触发 |

### 5.3 焦点逻辑的层级设计

BBLL 的焦点行为有几个关键特征，需要在 Web 方案中逐一还原：

1. **导航栏与内容区是两个独立焦点区域**。焦点在左侧导航栏时，按右键进入内容区；在内容区时，按左键回到导航栏。需要在 JS 中维护 `currentZone` 状态。

2. **焦点不会“丢失”**。BBLL 修复过多次“返回后焦点丢失”的问题。需要在页面切换时记住上一个聚焦元素的位置，返回时恢复。tvcontroller-javascript 本身不提供焦点记忆，需要手动保存和恢复 `lastFocusedElement`。

3. **横向滚动与纵向滚动分开处理**。在推荐行内按左右键是在卡片间移动，按上下键则是在行与行之间跳转。需要为每个内容行设置独立的 `tv-focus` 组，并限制方向键的移动边界。

4. **返回键行为**。Android TV 的返回键在 WebView 中会触发 `keydown` 事件（键码 4），默认行为是退出 WebView。需要在 `tv-back` 属性中拦截它，根据当前层级决定是“关闭 OSD → 返回上一页 → 退出应用”中的哪一步。

### 5.4 焦点视觉反馈

TV 端用户看不到鼠标，必须通过醒目的视觉反馈让用户知道当前选中了什么：

```css
.tv-focused {
  border: 3px solid #00a1d6;
  transform: scale(1.08);
  box-shadow: 0 0 20px rgba(0, 161, 214, 0.6);
  transition: all 200ms ease;
  z-index: 10;
}
```


## 六、API 调用策略

### 6.1 接口来源

B 站 Web 公开接口的收集整理可参考 `bilibili-API-collect` 项目，该项目旨在对 B 站 WEB、APP、TV 等客户端中散落在世界各地的野生 API 进行收集整理，运用了黑箱法、控制变量法、代码逆向分析、拆包及反编译法、网络抓包法等研究办法。主要接口包括：

- **视频信息**：`/x/web-interface/view`
- **推荐列表**：`/x/web-interface/archive/related`
- **搜索**：优先使用 `/x/web-interface/search/all/v2`（风控较宽松）
- **Wbi 签名**：部分接口需要 `wts` 与 `w_rid` 签名

### 6.2 登录方案

支持 TV 端二维码登录，通过 `TvQrcodeLogin` 实现。扫码完成后的回调数据可直接保存为 cookie 文件供后续请求使用。TV 端登录使用 `access_token` 而非 Web 端 Cookie，请求头需要携带 `access_token`。

### 6.3 风控应对策略

1. **使用 WebView 内发起的 fetch 请求**，而非在 Node.js 或原生层发起 HTTP 请求，确保请求携带完整的浏览器环境特征。
2. **优先使用风控较宽松的端点**，如搜索功能使用 `/x/web-interface/search/all/v2`。
3. **保持登录态**，通过 WebView 的 Cookie 机制维持 B 站登录。
4. **控制请求频率**，避免短时间内大量并发请求。
5. **准备降级方案**，如果某个接口被风控拦截，应有备用方案。


## 七、打包与部署

### 7.1 使用 Nitron 打包（快速通道）

```bash
# 1. 前端项目初始化
npm create vite@latest bilitv-web -- --template vue
cd bilitv-web

# 2. 安装依赖
npm install tvcontroller-javascript

# 3. 编写页面（见第二、五章）

```

### 7.2 使用 Capacitor 打包（稳健通道）

```bash
pnpm add -D @capacitor/cli
pnpm add @capacitor/core @capacitor/android
npx cap init com.yourname.bilitv BiliTV
npx cap add android
npx cap sync android
npx cap open android
```

在 Android Studio 中：**Build → Generate Signed Bundle / APK → 选择 APK → 创建/使用 keystore → 生成 APK**。

### 7.3 APK 安装到电视

```bash
adb connect <电视IP>:5555
adb install dist/app.apk
```

或通过 U 盘将 APK 拷贝到电视上安装。

## 九、已知风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| B 站风控加强 | 接口调用失败 | WebView 环境 + 登录态 + 频率控制 + 备用端点 |
