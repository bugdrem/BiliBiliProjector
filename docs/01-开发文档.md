# BiliTV-Web 开发文档（v3.0 · 修订版）

> 本文档基于《00-原始需求文档.md》（v2.0）修订。修订的原因是：**P0 技术验证阶段对 B 站接口的风控行为做了实测，原始文档中"WebView 内直接 fetch"的核心假设被证伪**。本文档给出修正后的可落地架构。

- **项目名称**：BiliTV-Web
- **目标平台**：Android TV（兼容 Fire TV、安卓平板横屏），目标 Android 8+
- **技术路线**：Web 前端（Vue 3 重写 B 站页面）+ Capacitor WebView 容器 + APK
- **UI 基准**：借鉴 BBLL（左侧导航 + 右侧内容、默认暗黑、大字号大热区）
- **文档版本**：v3.0（2026-09-27）

## 一、P0 实测结论（2026-09-27，curl 实测）

以下结论直接决定架构，均为当日真实请求验证：

### 1.1 WAF 按 Origin 白名单拦截

`api.bilibili.com` 前置 openresty WAF，对请求头 `Origin` 做**白名单**判断：

| 请求形态 | UA | Origin | 结果 |
|---|---|---|---|
| 裸请求 | 无 | 无 | **200** |
| 裸请求 | 浏览器 UA | 无 | **200** |
| fetch 型 | 浏览器 UA | `https://www.bilibili.com` | **200** |
| fetch 型 | 浏览器 UA | `https://m.bilibili.com` | **200** |
| fetch 型 | 浏览器 UA | `http://localhost:5173` | **403** |
| fetch 型 | 浏览器 UA | `https://appassets.androidplatform.net` | **403** |
| fetch 型 | 浏览器 UA | `null`（file://） | **403** |

**推论**：
1. WebView 内页面 origin 是 `appassets.androidplatform.net`（Nitron/Capacitor 默认），页面里任何 `fetch/XHR` 都会带该 Origin → **被 WAF 整体 403，连 CORS 预检机会都没有**。原始文档"WebView 环境降低风控"的假设不成立。
2. `Origin` 是浏览器控制的禁止伪造头，Web 层无解 → **必须让请求不经过浏览器 HTTP 栈**（原生层发请求），或经同源代理。
3. 无 Origin 的服务端请求畅通 → 开发期用 **Vite dev proxy**（Node 服务端转发，无 Origin 头）；打包后用 **CapacitorHttp**（原生 HTTP，无 Origin 头）。

### 1.2 JSONP 已下线

`?jsonp=jsonp&callback=cb` 参数已不被支持（返回 HTML 错误页），经典 `<script>` JSONP 通道**不可用**。

### 1.3 匿名播放链路完全可用（无需登录、无需 Referer）

以 `BV1xuhR6yEM3` 实测：

| 环节 | 接口 | 匿名结果 |
|---|---|---|
| 推荐流 | `/x/web-interface/popular?ps=20&pn=1` | code 0 |
| 视频信息 | `/x/web-interface/view?bvid=…` | code 0（含 cid、分 P） |
| 播放地址 | `/x/player/playurl?bvid&cid&qn=64&platform=html5&high_quality=1` | code 0，返回 MP4 durl |
| MP4 直链 | `*.bilivideo.com/*.mp4` | **免 Referer**，支持 Range（206 分段） |

**推论**：`<video>` 标签可直接流式播放，画质上限 720p（`high_quality=1`）。DASH 高画质需要登录态，列为 P4 升级项。
Wbi 密钥接口 `/x/web-interface/nav` 匿名可用（`code:-101` 但 `data.wbi_img` 照常返回），签名可离线完成。

### 1.4 打包工具选型修正

| 方案 | 结论 |
|---|---|
| **Nitron**（原首选） | **出局**。v3.1.0 真实存在、零 SDK 出包，但它是 9.6KB 纯 WebView 壳，**没有原生 HTTP 桥**，页面内 fetch 照带 appassets Origin → B 站接口全部 403。仅可作"UI/焦点遥控试用包"（API 报错但界面可验证）。 |
| **Capacitor**（原备选） | **正式采用**。开启 `CapacitorHttp` 插件后，`window.fetch` 被原生实现接管：请求走 Android 原生 HTTP 栈，**不带浏览器 Origin，天然绕开 WAF 白名单**，且代码仍写标准 fetch。 |

> 本机（Windows）当前无 JDK 17 / Android SDK，无法当场编译 APK。交付物包含：完整前端 + 已生成并配置好的 `android/` Gradle 工程，在任何装有 Android Studio 的机器上开箱即编。详见第七章。

**开发环境**（PC 浏览器调试）传输路径：
`浏览器 fetch('/bapi/...')` → Vite dev server 代理（Node 侧转发，剥掉 Origin）→ `api.bilibili.com`。

两环境代码同构，仅 API_BASE 不同（构建期 `import.meta.env.DEV` 决定）。

## 三、技术选型

| 层面 | 选型 | 理由 |
|---|---|---|
| 前端框架 | **Vue 3 + Vite** | 产物纯静态；组合式 API 足够，不引入 Pinia（状态简单，reactive + localStorage 即可） |
| 路由 | **自写 hash 路由**（约 60 行） | 页面仅 5 个，避免 vue-router 依赖；hash 路由规避 WebView 子路径 404 |
| 遥控器焦点 | **自研 FocusEngine** | tvcontroller-javascript（v1.0.4 实测存在）只有属性式聚焦/执行，**无分区管理、无焦点记忆、无空间导航边界**——这些恰是本项目核心复杂度（原始文档 5.3 节自己也承认要手写）。且其 `tv-enter="fn()"` 属性为字符串求值，有注入面。自研 ~300 行，可控可测 |
| 签名 | js-md5 | Wbi 签名需要 MD5，选最小依赖 |
| 弹幕 | 自研 canvas 渲染器 | 滚动弹幕仅需时间窗调度 + 位速计算，无重依赖 |
| 播放 | 原生 `<video>` + MP4 durl | P0 实测免 Referer、支持 Range；DASH（1080P+）留待 P4 引入 dash.js |
| 打包 | **Capacitor 7 + CapacitorHttp** | 见 1.4；安卓工程直接生成 |
| 哈希签名 | meta referrer no-referrer | MP4 直链实测免 Referer，但主动去掉页面 Referer 更干净（避免 appassets Referer 触发未知名风险） |

**明确不做**（v1 范围外）：
- 登录（Web QR 的 Set-Cookie 无法落入第三方 WebView 的 bilibili 域；TV token 登录需 appkey 签名体系）→ P4+ 单独立项
- 收藏夹/历史云同步 → 本地 localStorage 版先行
- DASH 多画质、直播 → P4

## 四、网络层设计

### 4.1 统一请求封装（api/http.js）

- `API_BASE`：DEV=`/bapi`（Vite 代理），PROD=`https://api.bilibili.com`
- 超时 10s（AbortController）；网络错误/5xx 重试 1 次，4xx 不重试
- B 站业务码翻译：`code!==0` 抛 `ApiError(code, message)`；`-412/-352` 识别为风控拦截，给出"稍后再试"文案
- 客户端限频：同一 host 请求间隔 ≥ 300ms 的串行队列（防抖触发风控）
- 响应只取 `{code, message, data}` 中的 data，调用方不接触原始结构

### 4.2 Wbi 签名（api/wbi.js）

- 首次请求 `/x/web-interface/nav` 取 `wbi_img.img_url/sub_url` 文件名 → `img_key + sub_key`，localStorage 缓存 24h
- 混淆表 `mixinKeyEncTab`（64 元素固定表）→ 取 `mixin_key`（前 32 位）
- 签名流程：参数追加 `wts`（秒级时间戳）→ 按 key 字典序排序 → value 过滤 `!'()*` → RFC3986 URL 编码拼接 → `w_rid = md5(query + mixin_key)`
- 对搜索接口 `/x/web-interface/wbi/search/all/v2` 生效

### 4.3 API 清单（api/bilibili.js）

| 方法 | 端点 | 说明 |
|---|---|---|
| `getPopular(pn, ps)` | `/x/web-interface/popular` | 首页推荐流，分页 |
| `getRanking(rid)` | `/x/web-interface/ranking/v2` | 排行榜（rid=0 全站） |
| `searchAll(keyword)` | `/x/web-interface/wbi/search/all/v2` | 聚合搜索，取 result_type=video |
| `getView(bvid)` | `/x/web-interface/view` | 视频详情：cid、分 P、UP 主、统计 |
| `getRelated(bvid)` | `/x/web-interface/archive/related` | 相关推荐（播放页"下一个"） |
| `getPlayUrl(bvid, cid)` | `/x/player/playurl?platform=html5&high_quality=1&qn=64` | MP4 durl（720p 上限） |
| `getDanmaku(cid)` | `/x/v1/dm/list.so?cid=` | XML 弹幕池 |
| `getWbiKeys()` | `/x/web-interface/nav` | wbi 密钥（匿名可用，实测） |

## 五、FocusEngine（遥控器焦点引擎）

### 5.1 数据模型

- **可聚焦元素**：带 `v-focusable` 指令 / `data-focusable` 属性的元素，引擎周期性收集其 `getBoundingClientRect()`
- **分区（zone）**：`data-focus-zone="name"` 标记容器（`sidebar` / `content` / `osd` / `keyboard` / 模态层）。空间导航只在当前 zone 内寻找候选，**从根上杜绝焦点漂到看不见的元素**
- **分区出口**：容器可声明 `data-zone-exit="left:sidebar"`，方向键在当前 zone 无候选时按出口表跳转分区（导航栏 ↔ 内容区的 BBLL 行为）
- **模态层栈**：`pushLayer(zone, triggerEl)` / `popLayer()`；OSD、选集面板、清晰度面板、退出确认框都是一层。返回键永远弹栈；关闭后焦点归还 `triggerEl`
- **每页焦点记忆**：路由离开时记录 `{zone, elementSignature}`（元素在 zone 内的索引路径），返回时恢复——修复"返回后焦点丢失"（BBLL 曾反复修的 bug）

### 5.2 空间导航算法

方向 dir ∈ {up, down, left, right}：
1. 候选集：当前 zone 内所有可见（offsetParent 非 null、rect 面积>0）可聚焦元素
2. 方向过滤：right → `candidate.left >= current.right - 8px`，依此类推
3. 评分：`主轴间隙 × 1 + 交叉轴中心距 × 0.35`，取最小者
4. 无候选 → 查分区出口表跳 zone；再无 → 停住（边界）
5. 命中后 `scrollIntoView({block:'nearest', inline:'nearest'})` 跟随滚动

### 5.3 按键映射

| 遥控器键 | WebView 事件 | 行为 |
|---|---|---|
| 方向键 | keydown Arrow* | 空间导航 |
| OK/确认 | keydown Enter (13) | 触发元素 `onEnter` |
| 返回 | Capacitor `App.backButton`（浏览器内映射 Esc） | 弹层栈 → 路由回退 → 退出确认 |
| 媒体键 | keydown (播放/暂停/快进快退) | 播放页直通播放器 |

### 5.4 视觉反馈

`.tv-focused`：3px #00a1d6 边框 + scale(1.06) + 蓝色辉光 + 180ms 过渡；卡片标题聚焦时由两行截断展开为完整两行。初始焦点：路由挂载后 `nextTick` 聚焦该页 `data-autofocus` 元素。

## 六、页面与播放器

### 6.1 布局（对照 BBLL）

- 左侧导航 200px 常驻：搜索 / 首页 / 分类(P2) / 动态(P2) / 直播(P2) / 我的 / 设置；底部暗色 `#0f0f14`
- 右侧内容区：24px 内边距，卡片网格 `repeat(auto-fill, 288px)`
- 全局暗黑主题：背景 `#121218`，卡片 `#1c1c26`，主色 `#00a1d6`，辅助粉 `#fb7299`
- 字号 ≥ 20px，可交互热区 ≥ 60px

### 6.2 页面清单

| 页面 | 路由 | 内容 |
|---|---|---|
| 首页 | `#/home` | Tab：推荐（popular 分页网格，焦点触底自动加载）/ 排行（ranking 网格） |
| 搜索 | `#/search` | 屏上 QWERTY 键盘（分区 `keyboard`）+ 关联词行 + 结果网格 |
| 播放 | `#/play/:bvid` | 播放器 + OSD + 选集面板（多 P）+ 相关推荐行 |
| 我的 | `#/mine` | 本地收藏 / 历史（localStorage），可删除单条 |
| 设置 | `#/settings` | 弹幕开关、关于、清除缓存 |

### 6.3 播放器 OSD（对照 BBLL 交互）

- 方向键任意键 → OSD 显现；5s 无操作隐藏；隐藏态下左右键 = ±10s seek，上键 = 唤出 OSD
- OSD 底部：进度条（缓冲条 + 播放头）+ 播放/暂停、±10s、选集、倍速、弹幕开关；OK 键呼出面板
- 选集面板：多 P 视频列出全部分 P（`view.pages`），单 P 隐藏入口
- 离开页面记录播放进度到历史，重新进入秒级续播（提示 toast）
- 弹幕：canvas 全屏覆盖，XML 池按播放时间调度，从右向左匀速滚动，密度控制（同屏 ≤ 30 条）

## 七、打包方案

### 7.1 Capacitor（正式包）

工程已生成并配置（`bilitv-web/android/`），要点：
- `capacitor.config.json`：`plugins.CapacitorHttp.enabled = true`（核心：fetch 走原生，绕 WAF；实测已写入 android 资产）
- `webDir: dist`，构建流程 `npm run build && npx cap sync android`
- Gradle：AGP 8.7.2 / Gradle 8.11.1 / compileSdk 35 / minSdk 23，**需 JDK 21**
- `AndroidManifest.xml` 已声明（本包内已配置完毕）：
  ```xml
  <uses-feature android:name="android.software.leanback" android:required="false" />
  <uses-feature android:name="android.hardware.touchscreen" android:required="false" />
  <category android:name="android.intent.category.LEANBACK_LAUNCHER" />
  ```
- 在装有 **JDK 21 + Android SDK（Platform 35）** 的机器上：`cd android && ./gradlew assembleDebug` → `app/build/outputs/apk/debug/app-debug.apk`
- 安装：`adb connect <TV_IP>:5555 && adb install app-debug.apk`，或 U 盘侧载

> 工程完整性说明：本机无 Android SDK，`cap sync` 的清理阶段被安全删除机制拦截，
> 尾段产物（capacitor.settings.gradle / capacitor.build.gradle / namespace / strings.xml /
> 模板 MainActivity 残留）已手工补齐并逐项核验，工程结构完整可直接编译。

### 7.2 Nitron（UI 试用包，可选）

已构建 `bilitv-web/apk/BiliTV-ui-trial.apk`（269KB，2 秒出包）。**包内 B 站接口必然 403**（见 1.4），仅用于在电视上验证 UI 布局与遥控器焦点操作，不作为交付通道。
注意：Nitron 产物默认写在 `dist/app.apk`，会被 `vite build` 清空，构建后需移至 `apk/` 保存。

## 八、风险与应对（更新版）

| 风险 | 等级 | 应对 |
|---|---|---|
| WAF Origin 白名单（已证实） | 高·已解 | CapacitorHttp 原生 HTTP / dev proxy；**永不在 WebView 内直连 api.bilibili.com** |
| 搜索接口 -412 风控 | 中 | wbi 签名 + buvid3 引导（finger/spi）+ 限频队列；失败降级到"热门" |
| MP4 直链将来加 Referer 校验 | 低-中 | 当前实测免 Referer；若失效，P4 切 DASH + 原生播放器 |
| 720p 画质上限 | 中 | 登录体系（P4+）解锁 1080P；UI 预留画质面板 |
| TV WebView 碎片化 | 中 | 目标 Android 8+；Vue 3 运行时对 Chromium 61+ 兼容；不用新语法裸特性（esbuild 目标 es2018） |
| Nitron 包内 API 403 | 已知 | 仅作 UI 试用，文档明示 |
| 接口非公开契约变更 | 中 | api 层单文件收敛，字段容错（可选链 + 默认值） |
